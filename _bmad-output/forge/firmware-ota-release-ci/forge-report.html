Outcome

Idea narrowed from “add OTA” to CI/release automation only: tag-driven Release assets for the existing device OTA contract, plus a PR/main host-tests workflow.

Locked decisions

  • No device OTA feature changes; keep dual-slot / HA / manifest contract.
  • Trigger: push strict vX.Y.Z → build (+ size gate) → draft → upload assets → publish.
  • Version: tag wins (CI injects); binary and manifest match the tag.
  • Assets: otc6_gateway.bin + generated manifest.json with version, url, sha256, size, release_url.
  • Host tests: every PR to main and every push to main; not a tag gate.

Rejected

  • Release-event trigger; publish-before-assets.
  • Match-or-fail / honor-system version policies.
  • Prerelease / suffixed-tag OTA channel.
  • Host tests as release gate; release-pipeline-only done.

Weak points that survived

  • A bad main can still be tagged and published (tests don’t gate tags).
  • Local/dev APP_FW_VERSION may never match any Release.
